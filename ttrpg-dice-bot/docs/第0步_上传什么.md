## 1. 解压后你应该看到什么

**Windows**：右键 zip →「全部解压缩」→ 下一步 → 完成
**Mac**：双击 zip

解压后得到一个文件夹 `ttrpg-dice-bot`，打开它，你应该看到这些：

| 名字 | 说明 |
|---|---|
| `README.md` | 项目说明（给人看的） |
| `CHECKPOINT.md` | 开发进度记录（给人看的） |
| `package.json` | 项目的"配置单" |
| `apps/` | **要上线运行的代码**（前端页面 + 后端 Worker） |
| `packages/` | **引擎与协议**（前后端共用的一份） |
| `tests/` | 测试脚本（不上线，用来验代码没坏） |
| `tools/` | 开发工具（不上线） |
| `legacy/` | M2 单机版存档，**只作对照，不上线** |
| `docs/` | 这几份说明文档（第0步 / 部署 / 测试清单 / 添加新规则指引） |
| `.github/` | GitHub 自动部署的配置（一个 yml 文件） |
| `.gitignore` | 告诉 Git"哪些东西别传" |

✅ **验证点**：打开文件夹，上面这些名字都在 → 解压正确。
❌ 如果里面还有一个叫 `ttrpg-dice-bot` 的文件夹套着（即 `ttrpg-dice-bot/ttrpg-dice-bot/apps/…`），说明解压时多套了一层 —— 打开**里面那层**再上传，或者把它移出来一层。

## 2. 必须有 / 绝不能有

### ✅ 必须有的（66 个源码与配置文件，缺一个就跑不起来）

**关键中的关键，这 5 个缺了一定失败：**
1. `apps/worker/wrangler.toml` —— Cloudflare 的部署配置（**没有它 Cloudflare 不知道怎么部署**）
2. `apps/worker/src/index.js` —— 后端入口
3. `apps/worker/src/room.js` —— 房间（Durable Object）
4. `apps/web/index.html` —— 你打开看到的那个页面
5. `packages/engine/src/*.js`（**24 个文件**）—— 掷骰引擎

其余按文件夹整体上传即可，不用一个个核对。

### ❌ 绝对不能有的（出现了就删掉）

| 名字 | 为什么 |
|---|---|
| `node_modules/` | 我本地测试时装的一大堆第三方库，几十 MB，**不能传**。✅ 你的 zip 里**没有**它 —— 如果你自己解压后看到有，说明混进了别的东西，删掉 |
| `.dev.vars` | 存放密钥的本地文件（仓库里只有 `.dev.vars.example` 这个样板，**这个可以传**） |
| `.DS_Store` | Mac 自动生成的垃圾文件 |
| 任何 `.zip`、`.rar` | 别把压缩包再塞进文件夹里 |
| 你自己的其他项目文件 | 只传这一个文件夹 |

> ✅ **验证点**：文件夹里**看不到** `node_modules` → 干净。
> 我已经在仓库里放了 `.gitignore`，它会自动帮你挡住这些，但你上传时还是自己看一眼最保险。

## 3. 传到 GitHub（**两条路，选你顺手的**）

### 路线 A：GitHub 网页端（不用装任何软件，推荐新手）

1. 打开 https://github.com → 登录 → 右上角 **+** → **New repository**
2. Repository name 填：`ttrpg-dice-bot`
3. 选 **Private**（私有）或 Public 都行，建议先 Private
4. **不要**勾 "Add a README file"（我们已有自己的文件）
5. 点 **Create repository**
6. 建好后页面中间有一行字 **"…or upload an existing file"** → 点它，是蓝色的链接
7. 把 `ttrpg-dice-bot` 文件夹**里面的所有内容**（注意：不是文件夹本身，是打开文件夹后的那些东西）拖到网页中间的虚线框里
   - 拖文件夹本身在部分浏览器不好使；如果拖不进去，就**全选里面的文件**一起拖
8. 页面下方显示文件列表 → 拉到底 → 点绿色按钮 **Commit changes**

✅ **验证点**：提交后回到仓库首页，应该看到 `apps`、`packages`、`tests` 等文件夹列在那儿。
点开 `apps/worker/` 应当能看到 `wrangler.toml`。
❌ 如果只看到一两个文件 —— 说明拖拽时只拖进去了一部分，重复第 7 步补齐。

> ⚠️ **GitHub 网页端一次最多传 100 个文件**，我们是 69 个，一次够。

### 路线 B：GitHub Desktop（装一个软件，但之后更省事）

1. 下载安装：https://desktop.github.com
2. 打开 → 登录 GitHub 账号
3. File → **Add local repository** → 选择你解压出来的 `ttrpg-dice-bot` 文件夹
   - 若提示"这不是一个 Git 仓库"，点 **create a repository**，路径就选这个文件夹，然后 **Create**
4. 左侧会列出所有改动 → 左下角 Summary 填 `M3 第一版` → 点 **Commit to main**
5. 顶部点 **Publish repository** → 名字 `ttrpg-dice-bot` → 勾掉/保留 Private 随意 → **Publish**

✅ **验证点**：浏览器打开 `https://github.com/<你的用户名>/ttrpg-dice-bot` 能看到文件 → 成功。

## 4. 常见疑问

**Q：我以前只传一个 `index.html`，这次为什么要传 69 个文件？**
A：以前是"把一张纸递给别人"，现在是"把一台机器搬过去" —— 机器有零件，零件分开装。
仓库里是**源码**，Cloudflare 会把它们组装好再运行。

**Q：那我以后改东西，还是网页端改吗？**
A：可以。但改的是源码里的某个文件，改完提交，Cloudflare 会自动重新部署。
（不像以前改 html 那样一步到位，但也不用你做什么额外操作。）

**Q：`legacy/M2_骰娘单机可摸版.html` 要传吗？**
A：要传，但它**不会上线**。它是 M2 单机版的存档，留着当对照。不影响部署。

**Q：我看不懂这些代码，会不会传错？**
A：不会。你只要保证**文件夹完整、没有 `node_modules`** 就行，代码本身不需要你动一个字。
