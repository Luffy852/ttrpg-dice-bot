# 部署指引（零基础版）

> **这份是给没有任何编程/命令行经验的人写的。**
> 全程**不用敲命令**（除非你主动想用），都在网页上点。
> 如果你会用命令行，看另一份《部署指引.md》。
>
> 前提：已经按《第0步_上传什么.md》把代码传到 GitHub 了。
> 日期：2026-10-29

---

## 先搞懂三件事（30 秒）

**① 这次和你以前做的有什么不一样**

| 你以前 | 这次 |
|---|---|
| 传一个 `index.html` 到 GitHub，Cloudflare 自动变成网页 | 传的是**一个完整的小程序**（前端 + 后端服务器） |
| 全程 GitHub 网页端就够了 | GitHub 存代码，但**真正让它跑起来的是 Cloudflare**，两边要连一下 |

**② "后端"是什么意思**
以前你的网页**没有服务器**，所有计算都在浏览器里做。
这次多了一个**服务器**（Cloudflare 的 Worker），负责掷骰子、存消息、广播给房间里所有人。
所以除了 GitHub，还要登录 Cloudflare 点几下。

**③ 你要去的两个网站**
- GitHub：`github.com` —— 存代码的地方（你已经传好了）
- Cloudflare：`dash.cloudflare.com` —— 让代码跑起来的地方（下面要做的）

---

## 第 1 步：登录 Cloudflare

1. 浏览器打开 https://dash.cloudflare.com
2. 登录你已有的账号

✅ **验证点**：登录后看到左侧或顶部有 **Workers & Pages** 这一项。
❌ 如果看到让你"添加站点/Add a site"的引导 —— 忽略它，那是给域名用的，我们不需要。

---

## 第 2 步：把 Cloudflare 和你的 GitHub 连起来（一次性）

1. 左侧点 **Workers & Pages**
2. 点 **Create**（创建）
3. 选 **Connect to Git**（连接到 Git）这一项
   - 页面上可能写作 "Import a repository" 或 "Connect to GitHub"，都是同一个意思
4. 第一次会让你**授权 GitHub** → 点授权 → 选 **Only select repositories** → 只勾 `ttrpg-dice-bot` → 保存
5. 回到 Cloudflare，应该能看到你的仓库 `ttrpg-dice-bot` → 点 **Begin setup**（开始设置）

✅ **验证点**：页面上出现了配置表单，能填项目名称。

---

## 第 3 步：填配置（**照抄，别改**）

页面上会有这些框，**按下面填**：

| 框的名字 | 填什么 |
|---|---|
| Project name / 项目名称 | `ttrpg-dice-bot` |
| Production branch / 生产分支 | `main` |
| Build command / 构建命令 | **留空**（什么都不填） |
| Deploy command / 部署命令 | **留空**（什么都不填） |
| Root directory / 根目录 | **留空**（什么都不填） |

> ⚠️ **为什么要留空**：项目里已经有一个 `wrangler.toml` 配置文件，
> Cloudflare 会自动读它，知道入口在哪、前端在哪、房间数据库怎么建。
> 你要是手动填了，反而可能跟它冲突。

然后点 **Save and Deploy**（保存并部署）。

✅ **验证点**：页面开始转圈，出现部署日志（一串英文在滚动）。
❌ 如果报错说找不到 `wrangler.toml` —— 说明第 0 步上传时漏文件了，回去看《第0步_上传什么》的第 2 节。

---

## 第 4 步：等第一次部署结束，看结果

部署要 1～3 分钟。结束后：

✅ **成功长这样**：页面上出现绿色 **Success**，并给你一个网址，形如：
```
https://ttrpg-dice-bot.xxxxx.workers.dev
```
**把这个网址复制下来存好**，这就是你的骰娘地址，以后都用这个打开。

❌ **失败长这样**：红色 **Failed**，下面有一堆红字。
→ **不要慌，也不要自己猜**。把红字**截图发我**，我来看。
（最常见的是 PIN 密钥还没设 —— 看第 5 步，设完重新部署就好。）

---

## 第 5 步：设一个密钥（PIN_SECRET）—— **必做，否则带口令的房间会挂**

这个密钥是用来给"房间口令"做签名的。**没有它，创建房间时如果勾了口令就会出错。**

1. Cloudflare 左侧 **Workers & Pages** → 点你的 `ttrpg-dice-bot`
2. 顶部点 **Settings**（设置）
3. 找到 **Variables and Secrets**（变量与机密）
4. 点 **Add**（添加）
5. 按下面填：
   - **Type / 类型**：选 **Secret（机密）** ← 一定要选这个，不要选 Text
   - **Variable name / 名字**：`PIN_SECRET`（**一模一样，全大写，中间是下划线**）
   - **Value / 值**：随便打一串长一点的乱字符，比如
     `MyDiceBot-2026-Secret-abc123xyz`
     （越长越乱越好；**自己记在别处**，设完网页上就不再显示了）
6. 点 **Deploy** / **Save**

✅ **验证点**：列表里出现一行 `PIN_SECRET`，类型是 **Secret**，值显示为 `•••••`（看不到原文，这是对的）。

> ⚠️ 这个密钥**不能写进代码里**，所以必须由你在这儿手动设一次。设一次就够了，以后不用管。

---

## 第 6 步：开网页验收（**先只做这一件事**）

浏览器打开第 4 步给你的网址。

你应该看到**进房页**：一个卡片，上面有"加入房间"和"创建房间"两个标签。

然后：
1. 点 **创建房间**
2. 昵称随便填一个，比如 `测试`
3. **不要**勾"给房间加口令"（第一次先不勾，少一个变量）
4. 点 **创建房间**
5. 应该跳进聊天页，顶栏能看到 6 位房间号
6. 在下面输入框打 **`.r 2d6+3`** → 点发送
7. 应该出现一个**可以点开的骰点气泡**，点开有"两颗骰子各是多少、合计是多少"

### ✅ 到这里就成功了一半。请停下来，做两件事：
- **把房间号记下来**（后面多设备测试要用）
- 打开《测试项目清单_小白版.md》，从 A 组开始勾

❌ **如果卡住了**：不要继续往下试，把"你看到了什么"截图发我。

---

## 第 7 步（可选）：以后怎么改

以后你想改代码（或我给你改好的新版本）：
1. 在 GitHub 上改文件（网页端铅笔图标）→ Commit
2. Cloudflare **会自动重新部署**，1～3 分钟
3. 刷新网页看效果

不需要你做任何额外操作。**不要**在 Cloudflare 上手动改代码，改了会被 GitHub 覆盖。

---

## 出问题时

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 打开网址是 404 | 还在部署，或部署失败 | 回 Cloudflare 看部署状态是不是绿 |
| 打开网址显示 "Application error" 或 1101 | `PIN_SECRET` 没设 | 做第 5 步，然后重新部署 |
| 页面能开但发指令没反应 | 后端没起来 | 截图发我 |
| 提示 "Durable Object migration required" | 数据库配置问题 | 截图发我，**不要**自己改 `wrangler.toml` |
| 房间建了但刷新后进不去 | 正常，需要房间号 | 用 URL 里的 `?code=123456` 或修改保存 |

**回滚**：Cloudflare → 你的 Worker → **Deployments** → 找到上一个成功的 → 点 **Rollback**。房间数据不会丢。

## 术语表（看到不懂的词来查）

| 词 | 人话 |
|---|---|
| Worker | 跑在 Cloudflare 上的后端小程序 |
| Durable Object（DO） | 每个房间一个的"小数据库"，存这个房间的消息 |
| SQLite | 数据库的一种，就当是"存消息的表格" |
| wrangler.toml | 告诉 Cloudflare 怎么部署的配置文件 |
| Secret | 密钥，设了之后网页上看不到原文 |
| Deploy / 部署 | 把代码变成能访问的网站 |
| Commit | 在 GitHub 上保存改动 |
