## 第一节 · 部署与上传

### 0. 先搞懂三件事（30 秒）

**① 这次和你以前做的有什么不一样**

| 你以前 | 这次 |
|---|---|
| 传一个 `index.html` 到 GitHub，Cloudflare 自动变成网页 | 传的是**一个完整的小程序**（前端 + 后端服务器） |
| 全程 GitHub 网页端就够了 | GitHub 存代码，但**真正让它跑起来的是 Cloudflare**，两边要连一下 |

**② "后端"是什么意思**
以前你的网页**没有服务器**，所有计算都在浏览器里做。
这次多了一个**服务器**（Cloudflare 的 Worker），负责掷骰子、存消息、广播给房间里所有人。
所以除了 GitHub，还要登录 Cloudflare 点几下。

**③ 你要去的两个网站**
- GitHub：`github.com` —— 存代码的地方（你已经传好了）
- Cloudflare：`dash.cloudflare.com` —— 让代码跑起来的地方（下面要做的）

### 2. 必须有 / 绝不能有

#### ✅ 必须有的（别数文件个数，认准下面 5 个就行）

**关键中的关键，这 5 个缺了一定失败：**
1. `wrangler.toml` —— **在仓库最外层**（和 `apps`、`packages` 并列），不是 `apps/worker/` 里面
2. `apps/worker/src/index.js` —— 后端入口
3. `apps/worker/src/room.js` —— 房间（Durable Object）
4. `apps/web/index.html` —— 你打开看到的那个页面
5. `packages/engine/src/*.js`（**25 个模块**）—— 掷骰引擎

其余按文件夹整体上传即可，不用一个个核对。

#### ❌ 绝对不能有的（出现了就删掉）

| 名字 | 为什么 |
|---|---|
| `node_modules/` | 我本地测试时装的一大堆第三方库，几十 MB，**不能传**。✅ 你的 zip 里**没有**它 —— 如果你自己解压后看到有，说明混进了别的东西，删掉 |
| 空的 `lib/` 或 `.scratch/` | 我这边留下的两个**空文件夹**，已在新压缩包里删掉。你手上那份如果还有，删掉或无视都行 —— 空文件夹不影响部署，GitHub 本来也不会收 |
| `.dev.vars` | 存放真实密钥的本地文件（已由 `.gitignore` 挡住，**绝对不能传**） |
| `.DS_Store` | Mac 自动生成的垃圾文件 |
| 任何 `.zip`、`.rar` | 别把压缩包再塞进文件夹里 |
| 你自己的其他项目文件 | 只传这一个文件夹 |

> ✅ **验证点**：文件夹里**看不到** `node_modules` → 干净。
> 仓库里的 `.gitignore` 会在本地 Git / Desktop 里自动挡住这些，但你用**网页端拖传**是手动勾选文件，
> 它拦不到已选中的项 —— 所以还是自己看一眼最保险。

### 3. 传到 GitHub（**两条路，选你顺手的**）

### 4. 常见疑问

**Q：我以前只传一个 `index.html`，这次为什么要传一百多个文件？**
A：以前是"把一张纸递给别人"，现在是"把一台机器搬过去" —— 机器有零件，零件分开装。
仓库里是**源码**，Cloudflare 会把它们组装好再运行。

**Q：那我以后改东西，还是网页端改吗？**
A：可以。但改的是源码里的某个文件，改完提交，Cloudflare 会自动重新部署。
（不像以前改 html 那样一步到位，但也不用你做什么额外操作。）

**Q：`legacy/M2_骰娘单机可摸版.html` 要传吗？**
A：**要传，而且必须留着**。它虽然不会上线，却是「生成前端页面」和「跑测试」要读的输入文件；
删了以后重新构建会直接报错。

**Q：我看不懂这些代码，会不会传错？**
A：不会。你只要保证**文件夹完整、没有 `node_modules`** 就行，代码本身不需要你动一个字。

**Q：怎么删掉仓库里不要的文件？**
A：**拖传只能新增或覆盖同名文件，永远不会删除**。要删得在 GitHub 网页端点进那个文件 →
右上角**垃圾桶图标** → Delete file → 最下面 Commit changes。全是点击，不用命令行。
（我给你更新包时会附一份「删除清单」，照着点就行。）

### 5. 上传与部署的三条长期规则

#### 规则 1：`packages/` 与 `apps/web/vendor/` 是同一份代码的两个位置

拖拽上传后 GitHub 会按包内目录自动放到对应路径，**覆盖同名文件即可**。

⚠️ `packages/engine/src/xxx.js` 与 `apps/web/vendor/engine/xxx.js` 内容必须一致
（vendor 给前端用，`index.html` 直接 import 它；`tools/` 下有同步校验，
`npm run check:all` 里的"静态资源自检"会比对）。

**只传一半**会出现「服务端有内容、页面仍空白」或反之 —— 这是本项目最典型的"传漏了"症状。

#### 规则 2：新文件也要传

我给的更新包会**包含新增文件**。如果你手工挑文件，记得带上新增的 —— 比如曾新增过：

| 新增文件 | 作用 |
|---|---|
| `apps/web/src/batch.js` / `apps/web/src/ask.js` | 批次分发 / 导出弹窗的实现 |
| `packages/protocol/src/export-filter.js` **和** `apps/web/vendor/protocol/export-filter.js` | 导出筛选的参数规范（前后端同一份，★必须成对传） |

---

#### 部署后

1. 等约 2 分钟自动部署
2. **强制刷新页面**（新开标签页更稳）
3. 旧房间的历史消息**不会**因为新代码自动补内容 —— 需要"补"的部分（比如某条消息原本缺字段）
   仍是老样子，这是设计如此，不是没部署成功

#### 如果 Cloudflare 报 `assets-upload-session` 失败（code 10013）

**这不是代码问题**，是 Cloudflare 自己的 Workers Assets 上传服务在故障（已知事件）。
**什么都不要改，直接 Retry build** —— 多数情况一次就过。旧版本继续在线上跑，不会中断。

⚠️ **千万别用"换个新 Worker 名字"来绕**：房间数据在 Durable Object 里，
而 DO 命名空间跟着 Worker 脚本名走 —— 改一次名字 = 全新命名空间 = **所有房间数据消失**。

### 第 3 步：填配置（**照抄，别改**）

页面上会有这些框，**按下面填**：

| 框的名字 | 填什么 |

### 第 5 步：设一个密钥（PIN_SECRET）—— **必做，否则带口令的房间会挂**

这个密钥是用来给"房间口令"做签名的。**没有它，创建房间时如果勾了口令就会出错。**

1. Cloudflare 左侧 **Workers & Pages** → 点你的 `ttrpg-dice-bot`
2. 顶部点 **Settings**（设置）
3. 找到 **Variables and Secrets**（变量与机密）
4. 点 **Add**（添加）
5. 按下面填：
   - **Type / 类型**：选 **Secret（机密）** ← 一定要选这个，不要选 Text
   - **Variable name / 名字**：`PIN_SECRET`（**一模一样，全大写，中间是下划线**）
   - **Value / 值**：随便打一串长一点的乱字符，比如
     `MyDiceBot-2026-Secret-abc123xyz`
     （越长越乱越好；**自己记在别处**，设完网页上就不再显示了）
6. 点 **Deploy** / **Save**

✅ **验证点**：列表里出现一行 `PIN_SECRET`，类型是 **Secret**，值显示为 `•••••`（看不到原文，这是对的）。

> ⚠️ 这个密钥**不能写进代码里**，所以必须由你在这儿手动设一次。设一次就够了，以后不用管。

### 出问题时

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 打开网址是 404 | 还在部署，或部署失败 | 回 Cloudflare 看部署状态是不是绿 |
| 打开网址显示 "Application error" 或 1101 | `PIN_SECRET` 没设 | 做第 5 步，然后重新部署 |
| 页面能开但发指令没反应 | 后端没起来 | 截图发我 |
| 提示 "Durable Object migration required" | 数据库配置问题 | 截图发我，**不要**自己改 `wrangler.toml` |
| 房间建了但刷新后进不去 | 正常，需要房间号 | 用 URL 里的 `?code=123456` 或修改保存 |

**回滚**：Cloudflare → 你的 Worker → **Deployments** → 找到上一个成功的 → 点 **Rollback**。房间数据不会丢。
